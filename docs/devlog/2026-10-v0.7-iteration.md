# v0.7 迭代开发日志 —— "可信与收口"

- 集成分支：`iteration/v0.7`（基于 `main` @ `af5e441`，即 v0.6.0 发布后）
- 开始日期：2026-10-02
- 方式与 v0.6 相同：主代理规划、复核、合并、验证、记录；Sonnet 子代理在 `.worktrees/<wp>` 独立 worktree / 分支实现各工作包。
- 设计依据：v0.6 发布前 Windows 实机测试暴露的两个升级路径缺陷（外部编辑重置 `onboarded`；BOM 导致设置全部重置）在 CI 上都未被发现；多账号、诊断、macOS 钥匙串等为半成品；59 个设置偏多；安装需绕过 SmartScreen / Gatekeeper。

## 目标与非目标

- 目标：让升级、降级、外部编辑、跨平台启动都有自动化证据；补齐 v0.6 的半成品；降低安装门槛；在已有数据上提供"帮你做决定"的建议。
- 非目标：新增服务商；任何默认开启的网络请求；读取会话内容（仍需显式开启）。

## 工作包

### 第 1 波

| WP | 分支 | 范围 | 验收 |
|---|---|---|---|
| WP1 升级与容错测试 | `wp/upgrade-tests` | 以 v0.3–v0.6 各版本的真实数据库结构与默认设置文件作测试样本，覆盖逐级迁移；`settings.json` 容错表驱动测试（BOM、半截写入、部分键、未知键、错类型、越界、CRLF、超大文件、空文件）；热加载与启动加载两条路径 | 每个历史版本样本迁移到最新后数据完整；容错用例无一导致设置被重置 |
| WP2 三平台启动与升级冒烟 | `wp/smoke-all` | Windows / macOS 启动冒烟脚本与 CI 任务（与 Linux 同标准：等待 `sidebar revealed`）；三平台"先装上一版发布、运行、再换新版"的真实升级冒烟 | CI 三平台冒烟全部通过，日志断言迁移成功 |
| WP4 降级安全 | `wp/downgrade-safety` | 迁移前自动备份（`VACUUM INTO`，保留最近 3 份）；`meta.min_reader_version` 兼容策略：以后只做可前向兼容的变更时旧版本仍可打开；新版遇到更新的库给出清晰提示而非失败；`--restore-pre-upgrade` 与设置页入口 | 单测覆盖备份轮转与兼容判断；文档写明策略 |
| WP5 设置减法 | `wp/settings-simplify` | 常用 / 高级分层（默认只显示常用）；审计 59 个设置，合并或移除冗余（如已废弃镜像键），带迁移；搜索仍可找到高级项 | 默认可见设置数显著下降；所有键仍可通过文件与搜索访问；AGENTS 对账通过 |

- Windows 代码签名：证书（PFX）或 Azure Trusted Signing 账号。
- macOS：Apple Developer 账号（签名证书、App 专用密码、Team ID）。
- 包管理器：winget 提交用的 GitHub token、AUR 账号 SSH 密钥、Homebrew tap 仓库（可由主代理创建，需确认）。
