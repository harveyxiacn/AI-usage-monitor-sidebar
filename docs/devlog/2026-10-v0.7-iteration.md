# v0.7 迭代开发日志 —— "可信与收口"

- 集成分支：`iteration/v0.7`（基于 `main` @ `af5e441`，即 v0.6.0 发布后）
- 开始日期：2026-10-02
- 方式与 v0.6 相同：主代理规划、复核、合并、验证、记录；Sonnet 子代理在 `.worktrees/<wp>` 独立 worktree / 分支实现各工作包。
- 设计依据：v0.6 发布前 Windows 实机测试暴露的两个升级路径缺陷（外部编辑重置 `onboarded`；BOM 导致设置全部重置）在 CI 上都未被发现；多账号、诊断、macOS 钥匙串等为半成品；59 个设置偏多；安装需绕过 SmartScreen / Gatekeeper。

## 目标与非目标

- 目标：让升级、降级、外部编辑、跨平台启动都有自动化证据；补齐 v0.6 的半成品；降低安装门槛；在已有数据上提供"帮你做决定"的建议。
- 非目标：新增服务商；任何默认开启的网络请求；读取会话内容（仍需显式开启）。

### 2026-10-02 · 限流（HTTP 429）排查与修复 — `744bfbd`

- 现象：维护者看到"服务商正在对用量接口限流——显示 2 分钟前的数据，4 分钟后重试"。日志：`claude usage API answered HTTP 429 (Retry-After: 30s)`，调度器遵守 30 s 并把学习间隔 ×2（120 s → 240 s），5 次成功后自动恢复；15:01 已恢复。
- 分析：本应用正常重启**不会**绕过 120 s 下限（启动时以缓存的 `fetchedAt` 作为上次请求时间，v0.6 起即如此）。当天额外请求来自主代理实机测试时用备份还原了较旧的缓存文件；即便如此本应用节奏约每 2 分钟一次。`/api/oauth/usage` 与 Claude Code 自身调用共享额度（ARCHITECTURE 已记载），维护者同时开着两个 Claude Code 会话——更可能是共享额度被用尽。
- 修复：① 手动刷新也遵守服务商下限（不再受学习/空闲拉伸与错误退避限制，仍遵守 `Retry-After`）；② `poll-state.json` 持久化 `lastAttemptMs`（无论成败），启动时与缓存时间取较晚者；③ 每次 429 记录"本应用最近 10 分钟发出的请求数"，用来区分"我们太频繁"和"同账号其他客户端占用"。新增 5 个单测；cargo test 525。文档：ARCHITECTURE、AGENTS、发布说明。
